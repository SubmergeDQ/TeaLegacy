# 方案 B：单应用 + 顶层分区（apps + shared）

> 状态：候选｜一次性工期 1.5 天｜功能开发 8.5 人日
> 一句话：仍是单构建单入口，但业务代码按「用户端 / 商家端 / 共享层」物理分区。

## 目标结构

```
src/
├─ main.ts                 # 唯一入口（保留）
├─ App.vue                 # 统一壳：按 route.meta.app 切布局
├─ shared/                 # 共享层
│  ├─ oil-ui/              # 由 src/components/oil-ui 迁入
│  ├─ styles/              # 由 src/styles 迁入
│  ├─ utils/               # 由 src/utils 迁入
│  └─ catalog/             # 只读数据 + 合并读取层
├─ apps/
│  ├─ user/                # 用户端：views、components/shop|craft、stores、router.ts
│  └─ merchant/            # 商家端（预留）：layout、views、components、stores、router.ts
```

## 迁移步骤

1. 建目录：`src/shared`、`src/apps/user`、`src/apps/merchant`
2. `git mv src/components/oil-ui src/shared/oil-ui`；`git mv src/styles src/shared/styles`；`git mv src/utils src/shared/utils`；`git mv src/catalog src/shared/catalog`
3. `git mv src/views src/apps/user/views`；`src/components/shop|craft` → `src/apps/user/components`；`src/stores` → `src/apps/user/stores`
4. 路由拆分：`src/router/index.ts` → `src/shared/router/root.ts` + `src/apps/user/router.ts`（商家端 router 后建）
5. 全局替换 import（约 45 文件、120 处）：
   - `@/views/` → `@/apps/user/views/`
   - `@/stores/` → `@/apps/user/stores/`
   - `@/components/oil-ui/` → `@/shared/oil-ui/`
   - `@/styles/` → `@/shared/styles/`
   - `@/catalog/` → `@/shared/catalog/`
   - `@/utils/` → `@/shared/utils/`
6. 可选：`tsconfig` 增加 `@user/* @merchant/* @shared/*` 别名，从 import 就能看出归属
7. `npm run typecheck && npm run build`，回归用户端 5 页

## 构建与分发

单构建、单 APK 双身份，与方案 A 相同。

## 优点 / 代价

**优点**：边界清晰，import 一眼看出归属；共享层已独立，将来迁 monorepo 只需把 `shared/*` 搬进 `packages/*`；仍是单包单 APK，演示成本低。
**代价**：没有构建隔离，商家端代码仍在用户端包里；一次性机械改动较大，需全量回归。
