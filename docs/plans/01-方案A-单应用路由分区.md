# 方案 A：单应用 + 路由分区

> 状态：**候选（推荐）**｜一次性工期 0.5 天｜功能开发 8.5 人日
> 一句话：在现有 Vite 应用里加一棵 `/admin` 路由树，商家端代码集中放 `src/merchant/`。

## 目标结构

```
src/
├─ merchant/                     ← 商家端（现已预留空目录）
│  ├─ layout/AdminLayout.vue     （新增：后台外壳 + 4 Tab）
│  ├─ views/                     （新增：登录/概览/商品/订单/设置）
│  ├─ components/                （新增：商品卡、订单卡、发货弹层）
│  ├─ stores/                    （新增：登录态、覆盖层、订单）
│  └─ router/index.ts            （新增：导出 merchantRoutes）
├─ catalog/admin/                （新增：契约 / Mock / 指标 / 合并读取层）
├─ components/oil-ui/            （增量：OTag OSwitch OStatCard OSheet OChart* 等）
├─ views/ stores/ components/shop|craft/   ← 用户端，不动
├─ router/index.ts               （追加一行：...merchantRoutes）
└─ App.vue                       （3 处 admin 判断）
```

## 路由

```ts
// src/router/index.ts
import { merchantRoutes } from './merchant'

routes: [
  ...现有用户端路由,
  ...merchantRoutes,   // /admin/login、/admin/dashboard、/admin/products …
]
```

子路由全部 `() => import(...)` 懒加载；`meta` 约定 `admin / tab / depth / title`（详见 [merchant-app.md](../architecture/merchant-app.md) 4.2）。

## 对现有代码的改动（仅 3 处）

1. `App.vue`：`showTabbar = route.meta.tab !== undefined && !route.meta.admin`
2. `main.ts`：返回键 fallback 按 `meta.section` 回 `/admin/dashboard` 或 `/craft`
3. `App.vue`：`keep-alive include` 可选追加商家端一级页

## 构建与分发

- 命令不变：`npm run build` → `dist/` → `npx cap sync android`
- 后台 chunk 独立懒加载，主包体积不变（实测基线：gzip 63 KB）
- 分发：单 APK，用户端商城页「承」印章长按 800ms → `/admin/login`

## 迁移步骤

1. `src/merchant/{layout,views,components,stores,router}`（已建空目录）
2. 数据层落 `src/catalog/admin/`（types → mock → metrics → 读取层）
3. Oil UI 增量组件 + 10 个图标，`index.ts` 注册
4. `src/router/merchant.ts` 定义路由表，`index.ts` 拼接
5. `App.vue` / `main.ts` 三处改动 + 登录守卫
6. `npm run typecheck && npm run build`，回归用户端 5 页

## 优点 / 代价

**优点**：最快、风险最低；与现有路由/转场/持久化范式完全一致；无新增依赖。
**代价**：商家端与用户端共享同一 `src/` 顶层，边界靠目录约定；将来拆包需再搬一次（约 1 天）。
